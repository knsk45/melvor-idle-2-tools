## MVP: рубка дерева

Один законченный экран, адаптированный под телефон и компьютер:

- Таблица: дерево, уровень доступа, время действия, опыт за действие, количество добычи, цена продажи, опыт/час, ресурсы/час, золото/час.
- Сортировка по опыту/час, золоту/час и уровню; поиск; фильтр «только доступное».
- Ввод уровня персонажа и подтверждённых модификаторов. До проверки механик допустим ручной ввод эффективных значений с понятной подписью.
- Базовый режим без бонусов и пользовательский режим; переключение не должно смешивать значения.
- Режим цели: количество ресурса и расчёт времени сбора.
- Сохранение настроек в localStorage с версией схемы и безопасным восстановлением при повреждении.
- Источник, версия/канал игры и дата проверки доступны возле данных.
- Кнопка сообщения об ошибке с предзаполненным Issue: объект, версия, ошибочное значение, ожидаемое значение, источник.
- Понятные пустые состояния: нет проверенных данных, нет доступных деревьев, некорректный ввод. Не показывать выдуманного победителя.

Отложить: аккаунты, синхронизацию сохранений, импорт игровых сохранений, боевые симуляторы, оптимизацию цепочек крафта, автоматический маршрут прокачки с переключением деревьев.

## Данные и достоверность

Данные Melvor Idle 1 нельзя использовать как факты для Melvor Idle 2. Не выдумывать значения и порядок применения бонусов. Демо, Patreon alpha и будущий релиз могут отличаться: хранить channel/build, не объединять несовместимые записи.

Приоритет источников: данные доступной пользователю сборки и наблюдения в игре; официальные описания механик/обновления; подтверждённые материалы сообщества. Любой автоматический импорт сначала исследовать отдельно: не предполагать существование API, формат файлов или разрешение на распространение файлов игры.

До получения проверенных значений сделать работающий интерфейс с пустым проверенным набором. Искусственные значения разрешены в тестовых fixtures и явно обозначенной песочнице, исключённой из игровых рекомендаций. Нужные данные можно запросить у владельца скриншотами или таблицей; тем временем продолжать независимую разработку.

Рекомендуемая запись: стабильный id, name.en/name.ru, requiredLevel, intervalSeconds, xpPerAction, expectedQuantityPerAction, sellPriceGp, channel, gameVersion, verificationStatus, checkedAt, sourceRefs. Неизвестные значения — null, а не ноль. Для вероятностной добычи хранить исходные вероятности/количества и явно вычислять ожидание. Происхождение полей при необходимости хранить отдельно.

Статусы: verified, provisional, unknown. Рекомендации по умолчанию строить на проверенных совместимых данных. Выводить полноту покрытия: «лучшее среди проверенных», если набор неполный.

## Расчёты

Для независимых повторяемых действий с постоянным эффективным интервалом t > 0:

```text
actionsPerHour = 3600 / t
xpPerHour = actionsPerHour * effectiveXpPerAction
itemsPerHour = actionsPerHour * expectedItemsPerAction
grossGpPerHour = itemsPerHour * effectiveSellPriceGp
expectedSecondsForQuantity = targetQuantity / itemsPerHour * 3600
```

Это ожидаемые долгосрочные показатели, без округления промежуточных значений. Для детерминированного целевого количества можно отдельно считать полные действия с округлением вверх; не выдавать ожидаемое время случайной добычи за гарантию.

Не называть выручку прибылью: если появятся расходники/расходы, показывать их отдельно и рассчитывать net GP. Для прямой продажи брёвен явно написать, учитываются ли побочные предметы, простои, офлайн-ограничения и расходы. Не добавлять неподтверждённые бонусы. Не переносить модель мастерства первой игры во вторую.

Пример только для unit-теста: t=4 с, XP=10, средняя добыча=2, цена=5 GP → 900 действий/час, 9000 XP/час, 1800 предметов/час, 9000 GP/час. Эти цифры не относятся к реальному дереву.

## Проверки и публикация

- Unit-тесты формул: известный пример, изменение интервала, нулевые/отрицательные интервалы, неизвестные поля, нулевая цена, целевое количество, исключение недоступных/неподтверждённых записей из рекомендаций.
- Валидатор: уникальные ID, корректные единицы и диапазоны, версии/каналы, существующие ссылки на источники; неизвестное не превращается в ноль.
- Проверить сборку, типы и lint. Проверить экран на мобильной ширине, сортировку чисел, клавиатурную доступность, локализацию и восстановление настроек.
- В Vite учесть base `/melvor-idle-2-tools/`; проверить загрузку ресурсов на вложенном пути. Для первого экрана не усложнять маршрутизацию.
- Настроить CI на PR; deploy Pages только из main. Перед публикацией показать результат и сообщить, что готово. Создание репозитория уже разрешено; дальнейший запуск публичного сайта выполнить после явного поручения пользователя либо подготовить workflow без запуска deploy.
- Не объявлять сайт опубликованным до успешного deployment и проверки адреса.
